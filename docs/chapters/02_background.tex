\chapter{Background and Problem Context}
\label{cap:background}
This chapter describes how the task of speech and music classification was first introduced to the public and how it evolved into the building block of most applications, followed by the definition and constraints of the on-line classifier.

\section{Historical Background}
Automatic classification of speech and music originated as a practical quality-of-life feature in radio broadcasting, enabling listeners to mute advertisements or switch between channels automatically~\cite {543290}.

The surge of ASR applications has made the audio classification task boom, as a need to detect speech in environments with much noise or music, because the applications would run unnecessarily or incorrectly~\cite {596192}

Today, speech–music classification is a fundamental component of modern audio processing systems.
It is used in voice-activated assistants, music streaming platforms, and telecommunication systems, where accurate content identification enables appropriate codec selection and efficient resource usage~\cite{ren2024fewertokenneuralspeechcodec, jia2025practicalrealtimeneuralvideo}.
Beyond consumer applications, it also supports large-scale infrastructures such as broadcast monitoring and audio archiving.

\section{On-Line Classification}
\label{sec:on-line_classification}
This thesis will use the definitions of the term 'on-line processing' according to Eyben's doctoral thesis~\cite{Eyben2016}.
On-line processing implicitly requires real-time processing; therefore, both terms are introduced.

\textit{"Real-time processing refers to processing of data in real-time. This implies two things: (a) the processing of the data requires less time than the duration of the data, i.e., the time it will take to record or play-back the data at normal speed, and (b) the processing lag is as low as possible, ideally zero."}

\textit{"On-line processing refers to processing of a continuous live stream of data while data are recorded or transmitted, i.e., computing and returning results continuously before the end of the data stream has been seen."}

After these definitions, on-line classification can be described as a process in which incoming data are processed continuously and classified into predefined classes without access to future samples, while maintaining low processing lag.

In practice, on-line processing usually requires the use of a buffer to aggregate incoming samples.
Once the buffer is filled, the classification is performed on the aggregated segment.
This aggregation introduces a delay between data acquisition and the availability of classification results, which is directly determined by the buffer size.
Consequently, the requirement for low latency limits the buffer duration to short time intervals, typically in the range of 10-30 ms.
For the use of features that require a longer temporal context, such as statistics computed over multiple frames, an additional buffer containing previous samples may be employed; however, the processing is still triggered by the primary buffer, and the resulting lag is therefore not eliminated.

Buffering is not the only source of delay in an on-line classification system.
Additional latency is introduced by the computational cost of feature extraction and classification, which must be completed after each buffer is processed.
Therefore, high computational complexity can significantly increase overall processing lag and compromise real-time operation.
For this reason, on-line classification requires the use of computationally efficient algorithms with predictable execution times.

\subsection{Constraints}
\label{subsec:constraints}
Based on the above considerations, the following constraints apply to the on-line classification approach used in this work:
\begin{itemize}
    \item \textbf{Causality}: The classification must be performed using only past and present samples, without access to future data.
    \item \textbf{Real-time operation}: All processing steps must be completed within the time duration of the processed data segment.
    \item \textbf{Low processing lag}: The delay between data acquisition and the availability of classification results must be minimized.
    \item \textbf{Limited buffer size}: Buffer durations must be kept short to satisfy latency requirements.
    \item \textbf{Bounded computational complexity}: Feature extraction and classification must have predictable and sufficiently low computational cost.
\end{itemize}
